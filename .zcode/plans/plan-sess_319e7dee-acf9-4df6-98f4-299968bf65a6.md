# MEER v5 — финальный план: аудит → реестры GT → benchmark → поэтапная реализация

## Зафиксированные канонические решения (ответы пользователя)
1. **Канон**: GT 5.07.07 (GregoriusT) — первоисточник эталонного контента; **GT5u 5.09.31 (Blood-Asp)** — целевой baseline; ничего из GT5.07.07 не теряется; дельта GT5U-vs-оригинал документируется отдельно; каждый источник — конкретный релиз/commit/SHA256.
2. **Аддоны**: полный реестр экосистемы GT 1.7.10 ДО реализации; GTNH-org ≠ исключение (TecTech/GoodGenerator исследуются); для каждого — происхождение/история/версии/совместимость/зависимости/лицензии/полный контент; классификация: оригинальный аддон / интегрирован в GT5u / GTNH-специфичный / standalone; GTNH — только идеи, его баланс/конфиги/эксклюзив — не канон; ничего не пропускать без документированного обоснования.
3. **Ассеты**: свои, максимально точные по GT-стилю; portable-папка для оригинальных текстур/моделей/звуков от пользователя с локальным переопределением; реестр ассетов (происхождение/автор/лицензия/SHA256); лицензия кода ≠ лицензия ассетов; без подтверждённых прав чужие ресурсы в сборку не включаются.

## Фаза D — Этапы (каждый = рабочая сборка + метрики до/после + тест корректности + откат)
- **S0** fork runnable: remap→decompile→game-src, свой bootstrap, клиент+сервер на JDK 27. M0.
- **S1** split + протокол v1: клиент без симуляции (linkage-проверка), сервер авторитетен; свой протокол (framing/versioning/AOI/delta snapshots/квантование/backpressure/защита от мусора/тесты рассинхрона); «Играть» = отдельный сервер-процесс + connect. M1.
- **S2** мир: async chunk-engine, packed palettes, dirty regions, event-driven, BFS-дельта свет, раздельные CPU-бюджеты, детерминированность. M2.
- **S3** рендер: probe реального драйвера iGPU, свой GL backend (VBO/persistent mapping по факту, батчинг, multithreaded meshing, culling, state sort, атласы), compat-фолбэк. M3.
- **S4** эффекты/звук/ресурсы: pools+LOD, async audio, индекс/дедуп. M4.
- **S5** сеть v2 + MP-стресс (2+ клиента). M5.
- **S6** GT волнами (каждая: срез реестра → своя реализация → матрица → бенчмарки): материалы/руды/жилы → LV-ядро (рудная цепочка) → энергосеть → MV/HV → жидкости/газы → мультиблоки → тепло/давление/взрывы → волны аддонов в порядке реестра. Никакого самодела, каждая механика трассируется в канон. M6 (после каждой волны).
- **S7** storage: свой формат + Anvil-импорт. M7.
- **S8** java-runtime: jlink из JDK 27; AOT cache vs AppCDS — измерить; GC по метрикам; Vector API/virtual threads — только при доказанном выигрыше; ≤60 МБ. M8.
- **S9/S10**: profiling/tests непрерывно; portable-финал: адаптивные профили, кириллица/пробелы/флешка, офлайн-аудит, BUILD_REPORT + zip. M10.

## §16 Аппаратная независимость
Hardware-probe модуль (CPU/RAM/GPU-возможности) при старте → адаптивные профили производительности (потоки/очереди/бюджеты масштабируются); ни одного захардкоженного предположения под 5600H; перенос = копирование папки; воспроизводимые сборки (пиннинг + SHA256).

## Верификация
Play: сервер-процесс → клиент → GT-цепочка → RU → сохранение/загрузка; 2 клиента ↔ 1 сервер; бенчмарки до/после каждого патча; матрица GT честно отражает %; обновление STATUS/WORK_LOG/BUILD_REPORT после каждой значимой работы. Видео: попытка yt-dlp; при блоке — жду .srt.

## Риски (кратко, полный в RISKS.md)
- Масштаб GT 1:1 (тысячи рецептов) → волны + матрица, честная незавершённость не выдаётся за 100%.
- Свои ассеты ≠ пиксель-паритет → папка переопределения пользователем сохраняет путь к полному соответствию.
- LGPL: код не копируем; ассеты — только свои или предоставленные пользователем.
