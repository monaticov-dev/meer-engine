# DECISIONS

Каждое решение: проблема → решение → почему → альтернативы → как проверяем → откат.

## D-001 База поведения — Minecraft 1.7.10, версия не меняется
П: нужен фиксированный эталон поведения/рецептов/прогрессии. Р: 1.7.10 (client.jar piston-meta, SHA1 сверен). П: спека §2. Откат: N/A (неизменяемое).

## D-002 Два процесса: авторитетный сервер + клиент-терминал
П: синглплеер запрещён; нужна предельная лёгкость клиента. Р: сервер = вся симуляция; клиент = рендер/ввод/звук/UI; «Играть» = запуск отдельного сервер-процесса + подключение. П: linkage-проверка (в клиенте нет классов симуляции), тесты рассинхрона. Откат: стадия S1 гейт.

## D-003 GT-канон и пиннинг источников
П: пользователь задал GT 5.07.07 (первоисточник) + GT5u 5.09.31 (baseline). ФАКТ: тега/релиза 5.09.31 в Blood-Asp/GT5-Unofficial НЕТ (полный ls-remote: серия 5.09.30.01–30.10, затем 5.09.33.01/.02; releases.atom подтверждает). Р: baseline = tag **5.09.33.02** (финал линии Blood-Asp, суперсет содержимого 31-й серии; commit SHA фиксируется после клона), GT 5.07.07 инвентаризируется из lineage GT5u (начальные коммиты = декомпил 5.07.07, подтверждено IC2-тредом) + jar-зеркало при нахождении. П: сравнение содержимого против вики/журналов изменений; GT_MATRIX отражает источник каждой позиции. Откат/вето: пользователь может заменить пин.

## D-004 GTNH — только идеи (спека §17)
П: GTNH запрещён как основа. Р: исследование механик/цепочек/UX разрешено; ни контента, ни баланса, ни конфигов GTNH-пака; GTNH-inspired механики получают отдельную метку происхождения в GT_REGISTRY и не смешиваются с каноном GT5/GT5u. П: регистр происхождения; аудит реестра. Откат: удаление помеченных позиций не затрагивает канон.

## D-005 Клиент — полностью собственный терминал (спека §18)
П: клиент не должен быть обёрткой над старым движком. Р: src/client пишется с нуля (bootstrap, свой GL-рендерер, GUI, звук, ввод); vanilla-1.7.10-форк = поведенческий эталон/оракул для соответствия; в клиенте ноль авторитетной симуляции; разрешены визуальное предсказание/интерполяция. П: снапшот-тесты, полнота функционального списка клиента (реестр функционала 1.7.10). Откат: стадийно.

## D-006 Сеть: интернет-режим сервера
П: у пользователя серийный/статический IP; сервер должен работать через интернет, не localhost. Р: bind 0.0.0.0:порт; при NAT — попытка автоматического проброса (UPnP/PCP/NAT-PMP); в консоль печатаются LAN IP и внешний IP:порт (внешний IP: из конфига `--public-ip` либо опционального запроса к указанному пользователем сервису — явное исходящее соединение, спека «все исходящие объяснены»); никаких привязок к localhost. П: интеграционный тест двух клиентов через внешний адрес; лог консоли. Откат: фолбэк ручного указания IP.

## D-007 Статическая выпечка вместо launchwrapper
П: FML 1.7.10 патчит классы в рантайме (LZMA→Pack200→GDiff) + деобф-ремаппер — тормоза старта и мусор. Р: StaticPatcher выпекает готовый jar на сборке (512 патчей применено статически, adler32-сверка входов, 15 lib-resident skip законны: realms/server/client-brand отсутствуют в client.jar). П: побайтовая детерминированность (фикс-таймстампы) — TODO S0; сравнение с рантайм-патчем по составу классов. Откат: вернуть рантайм-путь (существует в FML-исходниках).

## D-008 Целевая Java — JDK 27 (Temurin), сборка и jlink-runtime
П: «чем новее тем лучше» + своя минимальная Java. Р: runtime/jdk27 (Temurin 27.0.1+1); компиляция в bytecode 27 (без обратной совместимости — своя JRE); jlink+AppCDS/AOT на S8. П: запуск всех M-гейтов на jdk27; jdeps-отчёт. Откат: bytecode-уровень понижим конфигом.

## D-009 Ассеты: свои + папка переопределения пользователя
П: копирование чужих ассетов без прав запрещено. Р: собственные текстуры/звуки в GT-стиле; portable-папка `data/assets-override/` для оригиналов от пользователя; ASSET_LEDGER (происхождение/автор/лицензия/SHA256) обязателен для каждого файла. П: ревизия ledger перед каждой сборкой. Откат: N/A.

## D-010 Инструменты сборки пиннингуются
Р: Vineflower 1.12.0, SpecialSource 1.11.6-shaded, xz 1.9, MCP stable-12, MinGit 2.47.1.2 — SHA256 в docs/DEPENDENCIES.md. П: хеш-проверка в build-скрипте. Откат: версии фиксируются в реестре.

## D-011 Телеметрия/исходящие соединения
Р: рантайм — ноль исходящих, кроме: (а) игровые подключения к серверам, (б) явные/опциональные сервисы, заданные пользователем (напр. ip-echo для D-006). Сборочные загрузки — только на этапе сборки, список в DEPENDENCIES. П: сетевой аудит (статический grep URL + динамический лог соединений). Откат: N/A.

## D-012 Аппаратная независимость (спека §16)
Р: hardware-probe при старте (CPU/RAM/GPU/GL-возможности) → адаптивные профили (потоки/очереди/бюджеты); никакой привязки к Ryzen 5 5600H; перенос portable-папки = перенос всего. П: бенчмарки на профилях low/high; GL-версия проверяется по факту (не по названию GPU). Откат: ручной профиль в конфиге.

## D-013 Референс без FML; SpecialSource снят с критического пути
П: binpatched-классы требуют FML-рантайма; запуск патченного клиента без launchwrapper/FML — лишняя работа для оракула. Р: M0-референс = чистый vanilla client/server (обф-имена) на JDK 27 — запуск прямо; деобф через Vineflower --deobfuscation-map с нашим deobf.srg (SpecialSource из цепочки убран: его дескриптор-парсер падает на MCP-srg). Forge/FML = исходник для изучения хуков (каждый binpatch = точка интеграции, которую наши own-процессы реализуют нативно). П: M0 подтверждён запуском и скриншотом (benchmarks/M0-title-screen.png). Откат: SpecialSource вернётся, если понадобится remapped runtime-jar.

## D-014 JDK 27 + LWJGL2: факты запуска
Факты: lwjgl 2.9.1 работает на JDK 27 при `--enable-native-access=ALL-UNNAMED` + `-Djava.library.path`; vanilla-main требует полный набор аргументов лаунчера (--uuid/--accessToken/--userProperties/--userType); twitch-инициализация падает безопасно (вырежем). Вывод: рантайм-совместимость JDK 27 с игровым ядром 1.7.10 подтверждена запуском, не предположением. Клиент RSS 458 МБ при -Xmx1G; сервер "Done (3,016s)".

## D-015 СМЕНА БАЗЫ: старейшая РЕЛИЗНАЯ версия = 1.0 (2011-11-17)
П: пользователь «меняем в корне все… берём самую младшую… только релизы». Р: база поведения = релиз **1.0** (первый release); список всех релизов до 1.5.2 = 16 (1.0…1.5.2); portable-пакеты версий — на `C:\Users\User\Desktop\min\<version>\` (общая `_jre`, свои libs/natives на версию). 1.0 запущена и проверена (мир, пауза-меню, achievements). Формат версии 1.0: launchwrapper в json нам не нужен — в client.jar есть прямой `net.minecraft.client.Minecraft.main(String[])`; lwjgl_util 2.9.0 (артефакт с подчёркиванием!) — подвох, найден по NoClassDefFoundError GLU. GT-трек (1.4.7+ механики) — заморожен до явного решения пользователя: на 1.0 GregTech невозможен физически. Проверки: запуск + скриншот пауза-меню в мире. Откат: возврат к 1.7.10-базе (все артефакты/пайплайн сохранены).
